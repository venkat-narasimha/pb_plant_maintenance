1. Project Overview

The pb_plant_maintenance app extends ERPNext with enterprise Plant Maintenance (PM) capability modelled on SAP PM: master data (equipment, functional locations, task lists, measuring points), transactions (notifications, orders, confirmations, measurement documents), preventive planning, cost posting, reporting and REST APIs — all implemented as an upgrade-safe custom app with zero core modifications.

2.3 Core relationships

  • Asset 1—1 Equipment (via Equipment.asset_reference and Asset.pm_equipment custom field).
  • Functional Location 1—N Equipment; Equipment 1—N Notifications / Orders / Measuring Points.
  • Notification 1—1 Order (conversion); Order 1—N Confirmations; Order 1—N Operations & Required Parts.
  • Maintenance Plan 1—N Plan Tasks → auto-created Orders.
  • Order → Journal Entry (Journal Entry.pm_maintenance_order); Confirmation → Stock Entry (Stock Entry.maintenance_confirmation).

2.4 Status lifecycles

Notification: Draft→Open→In Progress→Converted to Order→Closed Cancelled

Order: Draft→Planned (on submit)→Approved→In Progress→Completed→Closed Cancelled

Confirmation: Partial · Final · Cancellation

4.1 Row-level security

  • Technicians see Maintenance Orders only where they are the owner or a member of the order’s maintenance_team (membership = Maintenance Team Member.team_member = User).
  • Operators see only Maintenance Notifications they reported.
  • Enforced via permission_query_conditions and has_permission hooks in utils/permissions.py.
ImportantA Technician with no Asset Maintenance Team membership sees zero orders by design. Always add technicians to a team (Step 15.4 of the build guide).

5. Standard Operating Procedures

SOP-01 · Create Equipment Planner / Manager

  1. Ensure the ERPNext Asset exists and is submitted (Assets → Asset).
  2. Workspace Plant Maintenance → Equipment → Add.
  3. Fill: Equipment Name, Asset link, Company (auto-fetched from Asset), Equipment Category, Criticality, Functional Location, Maintenance Team, Default Workstation.
  4. Save → ID EQ-####. Verify the Asset’s Maintenance section now shows the PM Equipment link.

SOP-02 · Report a problem Operator / Technician

  1. Open the Equipment → Create → Create Notification (or Notification List → Add).
  2. Type = Malfunction; set Short Description; tick Breakdown if the machine is down (auto-sets Priority=Critical and Malfunction Start).
  3. Save and Submit. Critical priority emails the PM Manager automatically.

SOP-03 · Plan the work Planner / Manager

  1. Open the submitted notification → Convert to Maintenance Order; confirm order type and planned window.
  2. On the order: verify Company / Cost Center / Equipment; add Operations rows (Workstation, Planned Hours, Assigned To) and Required Parts (item, qty, warehouse) if needed.
  3. Save and Submit → status becomes Planned.

SOP-04 · Execute & confirm Technician

  1. Open your order → Actions → Start Work (status → In Progress, actual start stamped).
  2. After the work: Actions → Record Confirmation; enter Operation #, Labor Hours, materials used (item/qty/warehouse) and Equipment Status After.
  3. Save and Submit:
    • Partial → order stays In Progress, operation marked In Progress.
    • Final → operation Completed, costs recalculated, order → Completed, labor Journal Entry posted, source notification closed, preventive plan tasks rescheduled.

SOP-05 · Close-out Manager

  • Actions → Complete Order (with completion notes) if not already completed by a Final confirmation.
  • Set status Closed manually when administratively finished.
  • Cancelling a confirmation reverts the order to In Progress; cancelling an order reverses Journal/Stock entries and stock reservations.

SOP-06 · Condition monitoring Technician

  1. Create a Measurement Document for a Measuring Point (or call API record_measurement).
  2. On submit the counter/last-reading updates; a reading outside lower/upper limits auto-creates a High-priority Maintenance Notification.

SOP-07 · Preventive planning Planner

  1. Create a Maintenance Plan: equipment/location, team, start date, tasks with periodicity (Daily…Yearly), optional Task List reference, Auto-Create Orders ✅, Lead Time days.
  2. The daily scheduler creates orders for due tasks and emails reminders lead_time_days ahead; completions reschedule the next due date automatically.

6.1 Multi-company rule (critical)

  • Every parent PM DocType carries a mandatory Company field, resolved in this order: explicit value → linked Equipment/Notification/Functional Location → Cost Center’s company → user default → Global Defaults.
  • All vouchers (JE/SE) use doc.company — never the user default company.
  • Validation blocks mismatched Cost Center / Equipment companies with an actionable error.
  • Patch backfill_company populated company on all pre-existing records.
Known site quirkThe Administrator user default company was “Processleap (Demo)” while PM data belongs to “Processleap”. It has been corrected, but if financial postings ever fail with a company mismatch, check the user default company and the company fields first.
